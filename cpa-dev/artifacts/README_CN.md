# CPA 批量导入 API Key

此版本给 CPA 管理面板增加「网关 → 密钥导入」，用于把**已签发、获准使用的 API Key**添加到现有的 OpenAI 兼容供应商（例如 FreeAi）。这是管理端扩展，不需要更换 CPA 后端或启用插件。没有部署到现有运行实例。

## 使用

1. 使用 CPA v8.1.2，在独立实例的面板目录部署同包的 `management.html`。复用 CPA 自己的管理鉴权。建议先在独立实例设置 `management.disable-auto-update-panel: true`，并确认其面板目录未与生产实例共用。
2. 登录新版面板，打开「网关 → 密钥导入」。选定目标供应商，逐行粘贴已取得的 API Key，每批最多 100 行。不要输入账号或密码。
3. 点击「导入到供应商」。右侧不经刷新显示校验、读取与去重、等待保存、完成，以及各行结果。结果仅含行号和状态，不显示密钥。阶段记录留在当前页面，切换供应商或离开页面后不会保留。

每批只写入一个已存在且可唯一识别的供应商。已存在的密钥和批次内重复项会跳过；其他有效行仍可保存。所有有效的新密钥在一次配置提交中追加。统一的现有密钥级代理设置会被沿用；如果设置不同，页面停止写入，不猜测出口。导入不会登录上游、验证密钥有效性、发现代理节点或改变代理节点。

## 写入与失败处理

- 通过 CPA 管理客户端读取和写入 `/v8/management/config/api-keys/openai-compatibility`。提交前重新读取目标配置，以强 ETag / `If-Match` 防止覆盖读取后发生的变更。
- CPA v8 按整个供应商族保存该数组。代码保留其他供应商及目标组的已有字段，但保存可能改变这部分 YAML 的文本排版或丢失注释；不保证逐字节不变。
- 遇到配置冲突不会自动覆盖或重试。先核对当前配置，再重新提交。若保存确认丢失，先在「AI 提供商」中检查新密钥是否已存在；请求中断不代表服务器回滚。
- 本模块没有注册账号、账号密码自动登录、自动确认 OAuth、浏览器内嵌或代理轮换功能。可在供应商官方流程取得密钥后再导入。

## 源码与构建

管理端基线：CPA Management Center `v1.29.2`，提交 `3866a16878b04c19627ef0db06a33f5cd79878cf`。后端契约：CLIProxyAPI `v8.1.2`，提交 `85225381d89915595598ed13766cd79890c03a84`。页面使用原管理端的 React、TypeScript、SCSS Modules、组件、主题和七语言资源。

在干净的管理端 v1.29.2 源码中应用同包补丁；当前已修改的源码目录无需重复应用。构建使用 Bun 1.4.3：

```powershell
bun install --frozen-lockfile
bun test tests/providerKeyImport.test.ts tests/localeParity.test.ts
bun run lint
$env:VERSION = 'v1.29.2-key-import'
bun run build
```

构建生成 `dist/index.html`，按 CPA 发布习惯作为 `management.html` 使用。交付面板 SHA-256：`AA9BF0F04CA897BA68D915DC0AF4C2CAFF663444EE34FB3FF61C03AB781B2276`。许可证见同包 `LICENSE`。
