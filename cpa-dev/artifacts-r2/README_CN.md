# CPA 批量导入 API Key · r2

这是 CPA Management Center v1.29.2 的原生管理页扩展，使用 CPA v8.1.2 的管理接口，把**已签发并获准使用的 API Key**追加到现有的 OpenAI 兼容供应商。无需额外服务、插件或后端改动。当前未部署到现有运行实例。

## 使用

1. 在独立 CPA v8.1.2 实例的面板目录使用同包 [management.html](./management.html)。如果启用了面板自动更新，先在该独立实例设定 `management.disable-auto-update-panel: true`，并确保资产目录没有与原实例共用。
2. 登录面板，进入 **网关 → 密钥导入**，选择目标（例如 `FreeAi`）。每行粘贴一把已经取得的 API Key，每批最多 100 行。不输入账号密码。
3. 点击「导入到供应商」。页面即时记录校验、读取与去重、保存及结果；仅显示行号与状态。切换目标或离开页面后不保留记录。

每批只写入一个已经配置且可以唯一识别的供应商。已存在项和批次内重复项会跳过；其他有效项可以在一次配置提交中追加。该模块沿用一致的已有密钥级代理设置，不自动更换出口；配置不一致则停止写入。导入过程本身不连接上游或代理。

## 保存确认与异常处理

- 提交前重新读取 `/v8/management/config/api-keys/openai-compatibility`，使用强 ETag 和 `If-Match`，防止覆盖读取后的并发更新。配置冲突时不再提交。
- r2 在保存结果不确定时，对同一 CPA 连接做一次只读回查，不自动重试写入。该供应商下可确认存在的密钥标记为「已回查：密钥存在」；未找到、目标已变化或回查失败时保留「保存结果待确认」。回查只证明配置中存在该密钥，不证明上游有效，也不保证没有其他操作者写入。
- CPA v8 的配置接口按供应商族整体保存。代码保留未修改的字段值，但这部分 YAML 的排版可能改变，注释可能丢失。正式部署前保留配置和原面板的备份。
- 该模块不包含批量账号注册、Google 账密自动登录、自动确认条款、内嵌浏览器或代理节点发现及轮换。可以在供应商的官方流程取得合法密钥后导入。

## 源码与构建

源码基线：管理端 `v1.29.2` / `3866a16878b04c19627ef0db06a33f5cd79878cf`。后端契约：`v8.1.2` / `85225381d89915595598ed13766cd79890c03a84`。页面复用 React、TypeScript、SCSS Modules、原有组件、主题、管理鉴权和七语言资源。

在干净的管理端 v1.29.2 源码中应用同包 [源码补丁](./provider-key-import.patch)；已有本地修改的源码目录无需重复应用。使用 Bun 1.4.3：

```powershell
bun install --frozen-lockfile
bun test tests/providerKeyImport.test.ts tests/localeParity.test.ts
bun run lint
$env:VERSION = 'v1.29.2-key-import-r2'
bun run build
```

构建生成 `dist/index.html`，改名为 [management.html](./management.html) 后由 CPA 托管。交付面板 SHA-256：`8BDEF4F8E9CC41E733D92D182893B2E4CE96574DE50374135D05149A96635F90`。许可证：[LICENSE](./LICENSE)。
